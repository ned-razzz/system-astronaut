<h1 align="center">System Astronaut</h1>

<p align="center">프로젝트 아이디어를 사용자 요구사항, 시스템 요구사항, 시스템 아키텍처로 구체화하는 세 가지 Agent Skill</p>

## 소개

System Astronaut는 프로젝트 설명을 바탕으로 요구사항과 아키텍처를 작성하거나 검토하는 세 가지 Agent Skill이다. 사용자가 얻고자 하는 결과를 분명히 하고, 그 결과를 위해 시스템이 해야 할 일과 필요한 구조를 연결한다.

```text
프로젝트 설명 → 사용자 요구사항(UR) → 시스템 요구사항(SR) → 시스템 아키텍처(SA)
```

각 스킬은 독립적으로 사용할 수 있다. 새 프로젝트를 구체화할 때는 위 흐름을 따르고, 기존 문서를 검토할 때는 필요한 단계의 스킬을 선택한다.

## 스킬 소개

| Skill | 목적 | 산출물 |
|---|---|---|
| [`astronaut-ur`](skills/astronaut-ur/SKILL.md) | 누가 무엇을 왜 원하는지, 어떤 결과를 성공으로 판단할지 정리 | 사용자 스토리와 수용 기준을 담은 사용자 요구사항 |
| [`astronaut-sr`](skills/astronaut-sr/SKILL.md) | 합의된 사용자 목표를 시스템의 기능·동작·품질 요구로 구체화 | 사용자 요구사항에 근거한 시스템 요구사항 |
| [`astronaut-sa`](skills/astronaut-sa/SKILL.md) | 합의된 시스템 요구사항을 실현할 하드웨어·소프트웨어 구조를 설계 | 구성 요소의 책임·배치·통신을 보여 주는 다이어그램과 설계 설명 |

`astronaut-ur`은 사용자가 제품에서 얻는 가치에 집중한다. 하나의 완결된 사용자 목표와 그 목표의 달성을 확인할 수 있는 수용 기준을 함께 정리한다. 수용 기준에는 수치뿐 아니라 관찰 결과를 바탕으로 한 사람의 판단도 사용할 수 있다.

`astronaut-sr`은 사용자 목표를 충족하기 위해 시스템이 해야 할 일을 설명한다. 주요 기능의 흐름과 예외·복구 동작, 필요한 품질 조건을 검토하여 구현과 검증의 기준이 될 요구사항을 만든다.

`astronaut-sa`는 시스템 요구사항을 실현할 구조와 그 근거를 설명한다. 필요한 실행 환경과 장치를 바탕으로 소프트웨어의 책임과 배치를 정하고, 구성 요소가 어떻게 협력하는지 보여 준다.

## 작성 의도

- **사용자의 의도를 보존한다.** 합의된 제품 범위와 목표의 의미를 유지하며, 미래 또는 선택적 기능도 정해진 조건에 따라 다룬다.
- **합의와 미결정을 구분한다.** 결정되지 않은 내용을 추측으로 채우지 않고 질문으로 남겨, 무엇을 더 결정해야 하는지 드러낸다.
- **요구사항과 설계의 근거를 연결한다.** 시스템의 기능과 구조가 어떤 사용자 목표와 요구사항에서 나왔는지 설명한다.

## 사용 흐름

1. 프로젝트 설명을 제공하고 `astronaut-ur`로 사용자 목표와 수용 기준을 정리한다.
2. 원본 문서의 사용자 요구사항을 모두 확정한 뒤, `astronaut-sr`로 시스템 요구사항을 작성한다.
3. 원본 문서의 시스템 요구사항을 모두 확정한 뒤, `astronaut-sa`로 아키텍처를 설계한다.

예를 들어 다음과 같이 요청할 수 있다.

```text
이 프로젝트 설명을 바탕으로 astronaut-ur로 사용자 요구사항을 작성해.
사용자 요구사항을 모두 확정했어. astronaut-sr로 시스템 요구사항을 작성해.
시스템 요구사항을 모두 확정했어. astronaut-sa로 시스템 아키텍처를 작성해.
```

기존 문서의 검토를 요청할 수도 있다.

```text
astronaut-sr로 이 시스템 요구사항의 누락, 모호한 동작, 사용자 요구사항과의 연결을 검토해.
```

## 설치

필요한 `skills/astronaut-*` 폴더를 사용하는 환경의 Skill 디렉터리에 복사해 설치할 수 있다.
