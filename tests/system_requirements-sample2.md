# 시스템 요구사항

행사장 로봇 카페 서비스의 시스템 요구사항이다. 운영자가 카페 트럭의 이동, 가게 준비와 배치, 주변 지도 준비를 완료한 이후의 자동 운영을 대상으로 한다. [user_requirements-sample2.md](./user_requirements-sample2.md)의 확정된 UR_01~UR_03을 근거로 도출했으며, 도출한 시스템 요구사항 자체는 아직 확정되지 않았으므로 상태는 모두 `proposed`이다. 각 Sub-SR은 상위 SR의 출처와 상태를 상속한다.

## Features

### SR_02 주문 접수와 제조·서빙 대상 연결

| Item | Content |
|---|---|
| Overview | 키오스크에서 선택한 상품과 수령 테이블을 하나의 주문으로 접수하고, 해당 정보를 자동 제조와 서빙에 연결한다. |
| State | proposed |
| Source UR | UR_01, UR_02 |

| Sub-SR | Name | Requirement |
|---|---|---|
| 01 | 상품과 테이블 선택 | 시스템은 손님이 키오스크에서 원하는 상품들을 선택하고 운영자가 등록한 테이블 중 수령 테이블을 선택할 수 있도록 해야 한다. |
| 02 | 주문 접수와 식별 | 시스템은 주문을 접수할 때 주문 상품들과 선택한 테이블을 함께 유지하고, 이후 제조·서빙 결과와 실패 내용을 해당 주문에 대응시킬 수 있도록 주문을 식별해야 한다. |
| 03 | 자동 처리 연결 | 접수된 주문은 선택한 상품들을 준비하는 제조 대상과 선택한 테이블에 상품들을 전달하는 서빙 대상으로 이어져야 한다. 시스템은 제조·인수·서빙 과정에서 상품과 수령 테이블의 주문별 대응 관계를 유지해야 한다. |

### SR_03 상품 준비와 픽업대 인계

| Item | Content |
|---|---|
| Overview | 접수된 주문의 상품들을 제조 로봇이 순차적으로 준비하고, 준비 완료 상품을 픽업대에 놓아 서빙 로봇이 인수할 수 있게 한다. |
| State | proposed |
| Source UR | UR_02 |

| Sub-SR | Name | Requirement |
|---|---|---|
| 01 | 상품 종류에 따른 순차 준비 | 주문이 접수되면 제조 로봇은 해당 주문의 상품들을 순차적으로 준비해야 한다. 핫도그는 직접 제조하고, 음료는 구비된 캔음료를 옮겨 준비해야 한다. |
| 02 | 준비 결과와 인계 확인 | 시스템은 상품별 준비 완료 여부를 확인하고, 준비가 끝난 상품들을 픽업대에 놓아야 한다. 픽업대에 놓인 상품은 해당 주문의 서빙 대상으로 식별할 수 있어야 하며, 준비 또는 픽업대 배치가 완료되지 않은 상품을 인수 가능한 완료 상품으로 처리해서는 안 된다. |
| 03 | 반복 준비와 중지 연결 | 시스템은 주문의 미완료 상품 준비를 자동으로 이어 가고, 모든 주문 상품의 준비 완료 여부를 구분해야 한다. 상품을 준비할 수 없으면 해당 주문의 자동 진행을 중지하고 SR_06의 주문 실패 처리로 이어져야 한다. |

### SR_04 서빙 로봇의 목적지 이동과 도착 확인

| Item | Content |
|---|---|
| Overview | 서빙과 모객에 공통으로 필요한 이동을 수행한다. 준비된 지도상의 목적지로 이동하고 도착 여부를 확인하여 각 활동의 다음 단계와 완료 판단에 제공한다. |
| State | proposed |
| Source UR | UR_01, UR_02, UR_03 |

| Sub-SR | Name | Requirement |
|---|---|---|
| 01 | 활동에 따른 목적지 식별 | 시스템은 운영자가 준비한 지도에서 주문에 지정된 등록 테이블, 픽업대 대기 위치, 운영자가 지정한 가게 바깥 모객 위치를 식별하고 현재 활동에 맞는 이동 목적지를 정해야 한다. |
| 02 | 자동 이동과 도착 확인 | 서빙 로봇은 지정된 목적지로 자동 이동하고, 시스템은 그 목적지의 도착 여부를 확인해야 한다. 테이블 서빙과 모객 안내는 해당 목적지 도착이 확인된 뒤 진행해야 하며, 픽업대 복귀는 픽업대 대기 위치의 도착이 확인되어야 완료로 판단해야 한다. |
| 03 | 이동 결과 구분 | 시스템은 목적지 도착이 확인되지 않은 이동을 완료로 처리해서는 안 된다. 이동 불가로 상품을 서빙할 수 없으면 해당 주문의 자동 진행을 중지해야 하며, 모객 활동의 이동 또는 복귀가 완료되지 않았으면 해당 활동을 정상 완료로 판단해서는 안 된다. |

### SR_05 주문 상품 인수와 테이블 서빙

| Item | Content |
|---|---|
| Overview | 서빙 로봇이 픽업대에서 해당 주문 상품들을 자신의 트레이에 올리고, 손님이 선택한 테이블에서 서빙한 뒤 다음 활동을 위한 대기 위치로 복귀한다. |
| State | proposed |
| Source UR | UR_01, UR_02 |

| Sub-SR | Name | Requirement |
|---|---|---|
| 01 | 주문 상품 인수 | 서빙 로봇은 픽업대에 준비된 해당 주문 상품들을 식별하여 자신의 트레이에 올려야 한다. 시스템은 트레이 인수 완료 여부를 확인하고, 다른 주문의 상품을 해당 주문 상품으로 인수하거나 인수가 완료되지 않은 상품을 서빙 대상으로 처리해서는 안 된다. |
| 02 | 지정 테이블 서빙 | 상품 인수가 완료되면 서빙 로봇은 SR_04의 이동 기능을 이용해 해당 주문에 지정된 테이블로 이동하여 트레이에 올린 주문 상품들을 서빙해야 한다. 시스템은 상품별 서빙 완료 여부를 확인하고, 주문 상품 전체의 서빙이 확인된 경우에만 해당 주문의 서빙이 완료되었다고 판단해야 한다. |
| 03 | 복귀와 반복 운영 | 서빙을 완료한 로봇은 픽업대 대기 위치로 복귀해야 한다. 복귀 후에는 다음 주문 상품의 인수·서빙 또는 SR_07의 모객 조건 판단을 이어 갈 수 있어야 하며, 운영 준비와 지도 준비 이후의 준비·인수·이동·서빙은 로봇들과 내재된 시스템으로 자동 진행되어야 한다. |
| 04 | 서빙 불가 연결 | 상품 인수, 테이블 이동 또는 테이블에서의 상품 전달을 수행할 수 없어 서빙이 불가능하면 시스템은 해당 주문의 자동 진행을 중지하고 SR_06의 주문 실패 처리로 이어져야 한다. |

### SR_06 주문 중지·재시도·취소와 진행 정보 제공

| Item | Content |
|---|---|
| Overview | 준비 또는 서빙 불가로 중지된 주문의 상태와 실패 내용을 전달하고, 운영자가 미완료 작업만 재시도하거나 추가 제조·서빙을 종료할 수 있게 한다. |
| State | proposed |
| Source UR | UR_02 |

| Sub-SR | Name | Requirement |
|---|---|---|
| 01 | 주문 단위 중지와 결과 유지 | 주문 상품을 준비하거나 서빙할 수 없으면 시스템은 해당 주문의 자동 진행을 중지해야 한다. 시스템은 중지 사유와 중지 시점까지 확인된 상품별 준비·인수·서빙 완료 여부를 해당 주문에 유지해야 하며, 완료 여부를 확인할 수 없는 작업을 임의로 완료 또는 미완료로 간주해서는 안 된다. |
| 02 | 손님 상태 확인과 운영자 알림 | 주문이 중지되면 손님은 키오스크에서 해당 주문의 미완료 상태와 사유를 확인할 수 있어야 한다. 시스템은 운영자에게 해당 주문과 실패 내용을 식별할 수 있는 알림을 제공해야 한다. |
| 03 | 미완료 작업 재시도 | 운영자가 중지된 주문의 재시도를 요청하면 시스템은 해당 주문의 확인된 진행 결과를 바탕으로 미완료 작업을 이어 가야 한다. 이미 완료된 제조·상품 준비와 서빙을 중복 수행해서는 안 되며, 다시 준비 또는 서빙이 불가능해지면 해당 주문의 자동 진행을 다시 중지해야 한다. |
| 04 | 주문 취소와 작업 종료 | 운영자는 중지된 주문을 취소할 수 있어야 한다. 취소하면 시스템은 해당 주문의 추가 제조·서빙을 종료해야 하며, 취소에 의한 종료를 상품 전체의 서빙 완료로 처리해서는 안 된다. |

### SR_07 유휴 상태 기반 모객과 서빙 우선 전환

| Item | Content |
|---|---|
| Overview | 자동 조건 또는 운영자 요청에 따라 한 차례 모객 활동을 수행하고 픽업대로 복귀한다. 새 주문 접수 또는 운영자 중지 요청이 있으면 활동을 중단하며 상품 서빙을 우선한다. |
| State | proposed |
| Source UR | UR_03 |

| Sub-SR | Name | Requirement |
|---|---|---|
| 01 | 자동 시작 조건과 반복 판단 | 시스템은 서빙 로봇이 픽업대 대기 위치에서 연속으로 유휴 상태에 있는 시간을 판단해야 한다. 미서빙 주문이 없고 그 연속 유휴 시간이 5분 이상이면 모객 모드를 자동 실행해야 한다. 대기 위치를 벗어나거나 유휴 상태가 끝나면 이전 유휴 시간을 새로운 연속 유휴 구간에 합산해서는 안 되며, 모객 후 복귀하여 다시 대기하면 같은 시작 조건을 새로 판단해야 한다. |
| 02 | 운영자 직접 시작 | 시스템은 미서빙 주문이 없고 서빙 로봇이 대기 중일 때 운영자가 모객 모드를 직접 시작할 수 있도록 해야 한다. 직접 시작에는 자동 시작의 5분 대기 조건을 요구해서는 안 된다. |
| 03 | 모객 수행과 정상 완료 | 모객 모드가 실행되면 서빙 로봇은 SR_04의 이동 기능을 이용해 운영자가 지도에 지정한 가게 바깥 모객 위치로 이동해야 한다. 도착 후 카페 안내 음성을 1회 재생하고 상품 정보를 표시한 뒤 픽업대 대기 위치로 복귀해야 한다. 시스템은 모객 위치 도착, 안내 음성 재생과 상품 정보 표시, 픽업대 복귀가 모두 완료되었는지 확인하여 활동 완료를 판단해야 하며, 방문자 수나 주문 증가량에 합격선을 두어서는 안 된다. |
| 04 | 중단과 서빙 우선 전환 | 모객 활동 중 새 주문이 접수되거나 운영자가 중지를 요청하면 시스템은 진행 중인 모객 활동을 중단하고 서빙 로봇을 픽업대로 복귀시켜야 한다. 이미 복귀 중이면 픽업대 복귀를 이어 가야 한다. 새 주문이 있는 경우 상품이 준비되면 모객보다 해당 상품의 서빙을 우선해야 하며, 중단된 모객 활동을 정상 완료로 처리해서는 안 된다. |

## System Constraints

### SR_01 자동 운영의 선행 조건과 대상 범위

| Item | Content |
|---|---|
| State | proposed |
| Source | [user_requirements-sample2.md](./user_requirements-sample2.md)의 도입부 및 `Excluded Scope` |
| Constraint | 시스템의 자동 운영 대상은 운영자가 카페 트럭의 행사장 이동, 가게 준비와 배치를 완료하고, 테이블·픽업대·가게 바깥 모객 위치가 표시된 주변 지도를 사전에 준비한 이후의 카페 운영이어야 한다. 지도는 운영자가 제공하는 선행 조건이다. |

## Excluded Scope

- 카페 트럭의 행사장 이동, 가게 준비와 배치의 자동화는 제품 범위에서 제외한다.
- 주변 지도 생성의 자동화는 제품 범위에서 제외한다. 운영자가 사전에 준비한 지도를 제공하는 것을 운영 선행 조건으로 한다.
