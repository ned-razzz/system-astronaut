# User Requirements

Turn a project brief into the smallest reviewable User Requirements artifact.

## Workflow

1. Identify actors, goals, and user-visible outcomes.
2. Write each requirement as a user story with acceptance criteria.
3. Preserve unresolved decisions as `open`; do not invent product decisions.
4. Mark scope and state explicitly using `confirmed`, `proposed`, `open`,
   `conflicted`, `out-of-scope`, or `n/a`.

## Output

Give each item a unique UR ID, user story, acceptance criteria, priority, and
state. Keep technical design and implementation choices out of UR.
