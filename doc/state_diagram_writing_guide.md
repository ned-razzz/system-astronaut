상태는 현재 수행 중인 기능 자체보다, **허용되는 이벤트와 이후 전이 경로**를 기준으로 정의한다.

### 1. 동일한 상태 간 전이는 하나의 화살표로 표현한다

한 상태에서 동일한 목적 상태로 향하는 전이는 하나로 표현한다.
여러 조건이나 이벤트가 같은 전이를 발생시키는 경우, 별도의 화살표를 중복해서 만들기보다 하나의 전이에 조건을 함께 정의한다.

### 2. 기존 상태로 표현할 수 있으면 새로운 상태를 만들지 않는다

현재 상태의 동작과 이후 전이 규칙으로 해당 기능을 충분히 표현할 수 있다면 별도의 상태를 정의하지 않는다.

필요한 경우 상태를 추가하는 대신 **이벤트명이나 상태명을 조정하여 의미를 명확히 한다.**

불필요한 상태 분리는 동일한 로직과 전이를 중복시키므로 피한다.

### 3. 수행 기능이 같아도 이후 흐름이 다르면 상태를 분리한다

물리적으로 동일한 기능을 수행하더라도 다음 중 하나가 다르면 별도의 상태로 정의한다.

* 허용되는 이벤트
* 다음으로 전이할 수 있는 상태
* 이벤트 발생 시 처리 방식
* 장애 및 복구 방식
* 상태가 유지해야 하는 데이터나 비즈니스 컨텍스트

예를 들어 `승차점 이동`과 `목적지 이동`은 모두 차량 이동을 수행하지만, 허용되는 이벤트와 이후 전이 경로가 다르므로 별도의 상태로 정의한다.

### 4. 진입 경로가 달라도 이후 동작이 같으면 상태를 통합한다

어떤 상태에 도달한 이전 상태나 진입 이벤트가 다르더라도, 진입 이후의 동작과 전이 규칙이 동일하다면 하나의 상태로 통합한다.

예를 들어 `사전 배치`와 `하차 대기`에서 서로 다른 이벤트로 `안전 정차`에 진입하더라도, 이후 수행 동작과 다음 상태가 동일하다면 `안전 정차`를 하나의 상태로 유지한다.

### 핵심 원칙

상태는 **"어떻게 들어왔는가"**보다 **"현재 무엇을 허용하고 이후 어디로 전이하는가"**를 기준으로 정의한다.

따라서 다음과 같이 판단한다.

* **이후 전이 규칙이 다르면 상태를 분리한다.**
* **이후 전이 규칙이 같으면 가능한 한 상태를 통합한다.**
* **기존 상태와 이벤트만으로 표현할 수 있으면 새로운 상태를 만들지 않는다.**
