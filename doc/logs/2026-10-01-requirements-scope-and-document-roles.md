# 전체 구현 범위와 요구사항 문서 역할 정리

작성일: 2026-10-01

이번 작업에서는 전체 구현 범위와 구현 우선순위를 구분하고, 사용자 목표·시스템 동작·구현
아이디어를 각 문서의 역할에 맞춰 정리했다. 이 로그는 논의와 수정 이력이며 요구사항의
승인이나 구현 완료를 뜻하지 않는다. 실행 코드는 변경하지 않았다.

앞선 [인식 실패 복구와 우선순위 기록](2026-10-01-recognition-recovery-and-priorities.md)의
MVP·후속 구분 및 `required/optional` 정의는 이후 논의에서 변경됐다. 현재 원칙과 실제
파일 상태를 아래에 기록한다. 처음 시도한 SR 보류·초안 별도 보존·AGENTS.md 변경은
사용자의 요청으로 되돌렸으며, 이후 명시적으로 요청한 문서 수정만 반영했다.

## 합의한 문서 역할

| 문서 | 역할 |
|---|---|
| [프로젝트 설명](../architecture_design/project_description.md) | 제품 목적, 전체 방향, 초기 관심 범위와 사용자에게 필요한 결과를 설명한다. 구체적인 구현 방식은 기술하지 않는다. |
| [UR](../architecture_design/user_requirements.md) | 구현하기로 합의한 전체 사용자 목표와 수용 기준을 명세한다. 나중에 구현할 기능도 포함하며 구현 우선순위는 넣지 않는다. |
| [SR](../architecture_design/system_requirements.md) | confirmed UR을 시스템 동작·품질·운영 조건으로 구체화한다. Priority는 전체 범위 안의 구현 순서를 나타낸다. |
| [구현 방향 참고 노트](../architecture_design/implementation_approach_notes.md) | 과거의 기술 방향과 검토 아이디어를 보존한다. source of truth가 아니며, 요구사항·승인된 기술 선택·확정 설계를 대신하지 않는다. |

전체 구현 범위는 현재 구현하기로 합의한 기능 전체를 뜻한다. 범위가 확장되거나 축소되면
UR을 먼저 갱신하고 관련 SR·설계·시험에 반영한다. 미래에 생각할 수 있는 모든 기능을
미리 명세한다는 뜻은 아니다.

`State`는 요구사항 내용의 합의 상태다. `Priority`는 구현 순서이며 포함·제외나 구현 완료
여부를 뜻하지 않는다. 기존 `required/optional`은 `P1/P2`로 변경했다. P1은 먼저 구현할
핵심 기능, P2는 그 다음에 구현할 기능이며 둘 다 전체 구현 범위에 포함된다.

## 질문을 관리하는 기준

처음에는 모든 미결정 사항을 UR의 Open Questions로 모으는 방안을 적용했다. 이후 사용자가
UR은 무엇을 구현할지 정하고 구체적인 시작 조건과 동작 정책은 SR에서 정한다고 설명했다.
이에 따라 시스템 세부사항을 UR 질문에서 다시 제거했다.

UR의 Open Questions에는 사용자 목표의 범위나 기대 결과에 관한 질문만 남겼다.

- UR_04: 행동 다양성의 평가 지표와 합격선.
- UR_05: 사람 유사성 평가 자료, 비교 지표, 관찰자 평가 방식과 합격선.
- UR_12~UR_13: 다른 플레이어 대응 범위와 채팅 답변 허용 조건.
- UR_16: 외부 기능의 사용자 관점 동작과 통합 합격 조건.

맵별 시작 구성, 키·화면 설정, HP·MP 임계값과 물약 보유 조건, 탐색·무처치 제한,
미인식 시 입력·복구·중단 조건, 성장 기준, 상태 갱신과 접근 권한은 SR에서 명세하도록
옮겼다. SR에는 Open Questions 섹션을 두지 않았다. 아직 값이나 정책이 정해지지 않은
항목은 proposed 초안이며, 질문을 제거한 것만으로 결정이 완료된 것은 아니다.

## 실제 문서 변경

### 사용자 요구사항

- 기존 UR_01~UR_16의 ID와 합의 상태를 유지했다. 상태를 일괄 confirmed로 바꾸지 않았다.
- 현재·후속·장기 단계 표현과 optional 표시를 제거하고 전체 구현 범위로 정리했다.
- 맵별 1시간 실행 3회 같은 MVP 시험 조건을 UR에서 제거했다.
- UR_03의 일시적인 인식 실패 복구를 전체 구현 목표로 기술했다.
- 사용자 목표 관련 질문만 남기고 시스템 동작에 관한 질문을 제거했다.

### 시스템 요구사항

- 기존 SR_01~SR_07과 남은 Sub-SR 식별자를 유지했다. SR의 상태는 proposed로 유지했다.
- 현재 MVP와 최종 목표의 구분을 제거하고 P1/P2를 구현 순서로 정의했다.
- 미인식 허용 시간에 따른 중단 정책 등 결정 전인 문장을 정리했다. 기존 SR_01_07은
  제거했으며 해당 ID를 다른 요구사항에 재사용하지 않았다.
- 시작 구성·자원 기준·미인식·시간 기준 등 시스템 동작 조건을 해당 요구사항과 Data에
  정리했다. 구체적인 값은 임의로 채우지 않았다.
- 기존 초안의 탐색 120초와 무처치 60초, 경험치 증가를 실제 처치 증거로 사용하는 내용을
  보존했다. 이번 보존으로 수치나 적용 정책이 새로 승인된 것은 아니다.
- UR에서 제거한 MVP 시험 조건을 SR에서도 제거했다. 24시간 무개입 운영 목표는 유지했다.
- 아직 confirmed가 아닌 UR은 Unused UR Inputs에 남겼다. 이는 전체 구현 범위에서
  제외했다는 의미가 아니라 SR 도출을 보류했다는 의미다.

### 프로젝트 설명과 참고 노트

프로젝트 설명에서 YOLO, 사전 지형 정보, Python·VIIPER, 처리 파이프라인, 모델 책임 분리,
기록 구성과 인터페이스 같은 구현 방식의 설명을 제거했다. 제품 목적과 기능 범위,
사용자가 확인할 결과를 중심으로 다시 작성했다.

삭제한 구현 아이디어는 구현 방향 참고 노트에 보존했다. 첫머리에 source of truth가
아님을 명시하고, 실제로 채택할 때는 UR·SR·설계에 반영해야 한다고 적었다. 프로젝트 설명에는
이 노트로 연결되는 링크를 추가했다.

프로젝트 설명의 사냥터별 1시간 무개입 실행 3회는 초기 검증 목표로 남아 있다.
UR·SR에서는 해당 MVP 시험 조건을 제거했으므로, 현재 SR의 확정된 검증 기준으로
간주하지 않는다.

## 독립 검토와 중단 의미 보완

사용자의 요청으로 하위 에이전트가 문서를 독립 검토했고, 주 에이전트가 결과를 대조했다.
검토에서는 미결정 시작 정책이 SR에 남은 점, 프로젝트 설명의 이전 시험 기준과 중복 질문,
중단 시 입력 처리의 의미가 사라진 점을 지적했다.

이후 사용자가 구체적인 시작 조건과 동작 정책은 SR의 책임이라고 명확히 했다. 따라서
이런 내용을 UR에 추가하는 대신 SR에서 구체화했다. 설정 불일치 시 시작 거절 여부를
묻던 UR 질문은 제거하고 SR의 시작 구성 설명을 정리했다.

중단의 의미는 다음과 같이 보완했다.

- UR_03: 중단 후 자동 플레이에서 추가 입력이 발생하지 않아야 한다.
- SR_01_08: 예약 입력을 취소하고 모든 키를 해제한 뒤 조작을 중지해야 한다.
- SR_01_08: 중단 후 예약 입력이 실행되거나 새로운 자동 입력이 발생해서는 안 된다.
- SR_01_08: 사용자에게 알리고 무개입 실행 실패로 기록해야 한다.

이 동작은 불확실한 상태와 키·화면 설정 변경으로 판단을 보장하지 못하는 상태에 모두
반영했다. 실패 후 재시작 조건은 아직 구체적으로 정하지 않았다.

[클래스 설계](../detailed_design/class_diagram.md)와
[시퀀스 설계](../detailed_design/sequence_diagram.md)의 질문 링크는 SR에서 UR로 변경했다.
이후 시스템 세부 질문을 UR에서 제거했으므로, 해당 설계 문서의 참조는 현재 SR의 관련
항목에 맞춰 다시 정리할 필요가 있다.

## 남은 결정과 문서 정리

- UR에 남은 사용자 목표 관련 질문을 해결하고 수용 기준에 반영한다.
- SR의 맵별 시작 구성과 자원 값, 미인식 허용 시간, 복구·중단·재시작 조건을 구체화한다.
- 탐색 120초와 무처치 60초의 기산점·초기화 조건·동시 적용 규칙을 정한다.
- 지원할 성장·퀘스트·육성 기준, 모니터링 정보의 갱신 기준과 접근 권한을 구체화한다.
- 사냥 지속성 검증 시간과 24시간 운영의 중단·재개·성공 판정을 정한다.
- SR_06·SR_07의 출처가 삭제된 프로젝트 설명의 「판단과 제어 방향」을 가리키므로,
  원래 외부 지정의 출처를 추적할 수 있도록 정리한다. 참고 노트를 승인 근거로 삼지 않는다.
- SR_04의 본문 행에는 검증 기준 셀이 있지만 표 헤더에는 해당 열이 없어 표를 정리해야 한다.
- 프로젝트 설명의 초기 시험 목표와 SR의 공식 검증 기준 사이의 관계를 정리한다.

## 확인한 범위

수정 과정에서 요구사항 ID·합의 상태·추적 관계와 질문 이동 내용을 확인하고
`git diff --check`를 실행했다. 문서 변경만 수행했으므로 실행 코드, 자동사냥 동작,
실제 중단 동작을 검증하는 테스트나 게임 실행 시험은 하지 않았다.

이번 로그는 현재 문서를 읽어 실제 반영 상태에 맞춰 작성했다. docs/logs는 기존
.gitignore의 제외 대상이므로 로컬 작업 기록으로 저장된다.
