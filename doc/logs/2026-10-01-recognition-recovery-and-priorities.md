이 기록은 [앞선 문서 검토 논의](2026-10-01-architecture-requirements-discussion.md)
이후 수행한 UR·SR 수정과 우선순위 지정을 정리한다. 앞선 기록에서 미정으로 남겼던
자동 복구의 적용 단계는 이번 논의로 정했으며, 시간 조건과 구체적인 복구 기준은
여전히 미확정이다. 이번 작업은 요구사항 문서 수정이며 구현 코드의 변경이 아니다.

## 1. 자동 복구와 현재 MVP 동작 구분

일시적인 인식 실패에서 자동으로 사냥에 복귀하는 동작은 최종 목표로 유지하되,
우선순위를 `optional`로 지정하고 현재 MVP 합격 조건에서 제외하기로 했다.
현재 MVP에서는 조작에 필요한 상태를 일정 시간 인식하지 못하면 실행을 중단한다.
합의된 목표를 현재 구현의 한계에 맞춰 삭제하지 않고, 적용 단계와 우선순위로
구분한다.

### UR_03 변경

사용자 이야기와 수락 기준에서 다음 동작을 구분했다.

- 몬스터가 보이지 않는 목표 부재 상황에서는 탐색을 이어 가고, 발견하면 사냥을 재개한다.
- 현재 MVP에서 조작에 필요한 상태의 미인식이 일정 시간 지속되면 중단하고 알린다.
  중단은 UR_02의 무개입 시험 실패로 기록한다.
- 일시적인 인식 실패의 자동 복구는 `optional` 최종 목표로 유지한다.
- 계속 행동하면 결과를 예측하기 어려운 상태에서는 중단하고 알리며 실패로 기록한다.

UR_03의 `confirmed` 상태는 유지했다. `optional`은 수락 기준 안에 명시했으며,
사용자가 정리한 UR의 열 구조는 유지했다.

### SR_01 변경

SR_01의 Overview를 현재 MVP와 최종 목표의 구분에 맞춰 갱신했다.

| 항목 | 변경 내용 |
|---|---|
| SR_01_05 HP·MP 미인식 처리 | 즉시 중단하던 요구를 미인식이 허용 시간 동안 지속되면 예약 입력 취소·모든 키 해제·중단·실패 기록·알림을 수행하도록 변경했다. |
| SR_01_07 위치 미인식 중단 | 위치 미인식도 허용 시간 동안 지속되면 중단하도록 변경했다. 기존의 재관찰·자동 복귀를 금지하는 표현은 제거했다. |
| SR_01_09 일시적인 인식 실패 자동 복구 | 캐릭터 위치나 HP·MP 상태를 다시 판단할 수 있게 되면 사용자 개입 없이 이동 또는 사냥을 재개하는 요구를 추가했다. 우선순위는 `optional`이다. |
| Data | 미인식 허용 시간의 의미를 추가했다. 구체적인 값과 시간 측정 조건은 미확정으로 남겼다. |
| Open Questions | 허용 시간의 값·기산점·초기화 조건, 대기 중 입력과 인식 회복 시 실행 처리, 후속 자동 복구의 적용 범위와 성공·실패 기준을 추가했다. |

물약 고갈 및 예측할 수 없는 상태에서의 중단 정책은 유지했다.
SR의 `proposed` 상태와 기존 식별 번호도 유지했으며, 자동 복구에는 새 Sub-SR
번호 `09`를 부여했다. 사용자 지정의 `Requirement`·`Priority` 표 형식은 유지했다.

## 2. 나머지 Priority 지정

기존 MVP·후속 단계 구분을 기준으로 SR 표의 빈 Priority 셀을 모두 채웠다.
두 값의 의미를 문서에 명시했다.

- `required`: 현재 MVP에서 반드시 충족해야 하는 요구사항이다.
- `optional`: 최종 목표로 유지하되 현재 MVP 합격 조건에는 포함하지 않는다.

우선순위는 합의 상태나 구현 완료 여부를 뜻하지 않는다. 이번 지정은 MVP 포함
여부를 구분하며, 같은 우선순위 안의 세부 구현 순서는 정하지 않았다.

| 요구사항 범위 | 지정 결과 |
|---|---|
| SR_01 자동사냥의 기존 동작·중단 요구 | required |
| SR_01_09 일시적인 인식 실패 자동 복구 | optional |
| SR_02 자동 성장 | optional |
| SR_03 다중 PC 모니터링 | optional |
| SR_04 MVP 사냥 지속성과 생존 | required |
| SR_05 장시간 운영 지속성 | optional |

조건별 분기를 각각 한 행으로 세면 `required`는 15행, `optional`은 10행이다.
이 수치는 고유 SR·Sub-SR 개수가 아니라 Priority가 지정된 요구사항 행 수다.
Priority 열이 없는 SR_06·SR_07의 제약 표는 변경하지 않았다.

## 3. 행동 다양성은 전체 SR 정리와 함께 처리

행동 다양성의 SR 누락은 후속 전체 SR 정리 작업에 포함하기로 했다.
그때 UR_04의 범위, 우선순위, 검증 기준을 함께 논의해 반영한다.
이번에는 UR_04와 `Unused UR Inputs`의 관련 항목을 변경하지 않았다.

## 4. 남은 결정 사항

- 위치 및 HP·MP 미인식의 허용 시간, 시간 측정 조건, 대기 중 입력 처리와 인식 회복 후 동작.
- 최종 자동 복구의 적용 범위, 성공·실패 판정과 복구 실패 시 중단 조건.
- 탐색 120초와 무처치 60초 기준의 적용 관계.
- 전체 SR 정리 때 반영할 행동 다양성 요구와 검증 기준.
- 프로젝트 설명의 자동 복구 관련 MVP 서술과 변경된 UR·SR의 단계 구분 정합성.
  프로젝트 설명은 이번 수정 대상에 포함하지 않았다.

## 5. 검증과 작업 범위

수정한 UR·SR의 관련 내용을 확인했고, 모든 요구사항 행의 Priority가 채워졌음을
확인했다. `git diff --check`는 통과했다. 문서만 수정했으므로 pytest나 게임 실행
시험은 수행하지 않았다. 구현이 이 요구사항을 충족하는지는 이번 작업에서 검증하지 않았다.

사용자가 수정한 제목과 표의 열 구조를 유지했다. 요구사항 문서 수정은 UR과 SR에
한정했고, 이 로그는 이후 변경 경위를 추적할 수 있도록 별도로 추가했다.
