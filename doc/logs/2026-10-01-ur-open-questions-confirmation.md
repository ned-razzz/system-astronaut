# UR 미결정 질문 확정과 요구사항 인터뷰 개선 기록

작성일: 2026-10-01

이번 작업에서는 [사용자 요구사항](../architecture_design/user_requirements.md)의
Open Questions를 사용자와 논의하고, UR_04·UR_05·UR_16의 수용 기준과 합의 상태를 갱신했다.
이 로그는 system-astronaut 개선에 사용할 결정 근거와 인터뷰 과정의 기록이다.
`confirmed`는 요구사항 내용에 합의했다는 뜻이며 구현이나 실행 검증의 완료를 뜻하지 않는다.

## 작업 목표와 질문 범위

처음 요청은 Open Questions 결정과 SR 개선이었다. 사용자는 논의 중 목표를
UR의 미결정 내용을 확정하여 `confirmed`로 바꾸는 작업으로 좁혔다.
이에 따라 이번에는 UR만 수정했으며 SR 도출과 수정은 수행하지 않았다.

질문 범위는 앞선 [문서 역할 정리 로그](2026-10-01-requirements-scope-and-document-roles.md)를
기준으로 잡았다. UR에서는 사용자 목표와 기대 결과를 결정하고, 구체적인 시스템 동작 정책과
검증 절차는 SR에서 정한다. 사용자는 이 구분을 질문 범위와 제약에도 반영하도록 요청했다.

현재 문서에는 UR_04·UR_05·UR_16의 질문만 남아 있었다. 이전 로그에서 질문 대상으로
기록한 UR_12·UR_13은 현재 문서의 Excluded Scope에 있으므로 다시 질문하지 않았다.
`grill-me` 요청에 따라 grilling 절차를 적용하되 필요한 결정만 물었다.

## 질문과 사용자 결정

### UR_04: 동일 작업 명령의 행동 다양성

첫 질문에서는 다양성의 의미와 평가 범위를 확인했다. 사용자는 같은 명령을 내렸을 때
다양하게 수행하는지를 보면 된다고 답했다. 후속 질문에서는 같은 명령의 단위를 확인했다.

사용자가 말한 단위는 정해진 위치로 이동하거나 대상을 추적·공격하는 작업 명령이다.
관찰 대상은 명령을 수행하는 실제 움직임이다. 매번 다른 경로나 행동을 강제할 필요는 없으며,
기계적으로 정해진 위치와 행동만 반복하는 느낌이 없으면 된다.

따라서 수용 기준에 동일 작업 명령의 반복 수행에서 다양한 움직임을 관찰할 수 있다는 점과
사용자가 기계적인 반복 여부를 판단한다는 점을 반영했다. 수치 지표나 합격선을 새로 정하지 않았다.

### UR_05: 사람 플레이와의 비교 평가

첫 질문에서는 자연스러움을 판단하는 방법을 확인했다. 사용자는 키 입력의 분포와 패턴을
시각화하고 실제 사람 플레이와 비교해야 한다고 답했다. 시스템은 시각화와 지표를 제공하고,
사람이 이를 보고 자연스러움을 판단한다.

후속 질문에서는 비교에 사용할 사람 플레이 기록을 확인했다. 사용자는 학습 데이터에서
기록 하나를 선택하거나 여러 기록을 함께 비교하면 되며, 특정 플레이어의 신원은 중요하지
않다고 답했다.

수용 기준에는 하나 이상의 학습 기록과 자동 플레이 기록을 비교하는 시각화·지표를 반영했다.
자동 합격 판정이나 익명 관찰자 판별 시험은 필수로 요구하지 않는다고 정리했다.
사냥 지속성과 실패 결과를 사람 유사성 비교 결과와 구분해 확인하는 기존 기준도 유지했다.
구체적인 지표 종류와 계산·표시 방법은 이번에 결정하지 않았다.

### UR_16: 외부 개발 기능의 실제 통합 결과

첫 질문에서는 연결 자체와 실제 동작 중 어디까지를 기대하는지 확인했다. 사용자는 외부
기능을 연결한 실제 시연에서 정상적으로 작동하여 장기간 플레이가 가능해야 한다고 답했다.

후속 질문에서는 목표 시간과 관찰할 결과를 확인했다. 사용자는 거짓말탐지기를 해결하지
못하면 일시 차단되므로, 해당 상황이 실제로 발생해도 외부 기능이 처리하여 목표 시간까지
자동사냥을 지속해야 한다고 설명했다. 처음 말한 23시간은 이후 24시간으로 정정했다.

수용 기준에는 24시간 무개입 자동사냥 기록과, 시연 중 해당 상황이 실제 발생했을 때 외부
기능의 처리 결과 및 사냥 지속 기록을 반영했다. 이번 작업에서는 외부 기능의 구현 방식이나
실제 성능을 검증하지 않았다. 발생 빈도나 시연 중 반드시 발생한다는 보장도 확정하지 않았다.

## 실제 반영 결과

| 항목 | 반영 내용 | 상태 |
|---|---|---|
| UR_04 | 동일 이동·추적·공격 명령에서 관찰되는 움직임 다양성과 사용자 판단 | confirmed |
| UR_05 | 학습 기록과 키 입력 분포·패턴의 시각화 및 지표 비교, 사람의 자연스러움 판단 | confirmed |
| UR_16 | 외부 기능이 실제 동작하는 24시간 무개입 자동사냥 시연 결과 | confirmed |
| Open Questions | 해결된 질문을 제거하고 현재 미해결 사용자 목표 질문이 없다고 명시 | 정리 완료 |

다른 UR의 상태는 변경하지 않았다. UR_06은 여전히 `proposed`다. 따라서 Open Questions가
비었다고 해서 모든 UR이 확정됐다고 해석하면 안 된다. 현재 문서에서 관리하던 세 질문이
해결됐다는 의미다.

## system-astronaut 개선에 사용할 시사점

아래 내용은 이번 대화에서 도출한 개선 제안이다. 스킬에 반영하거나 승인한 규칙은 아니다.

1. **질문 전에 현재 문서와 이전 로그를 대조한다.** 로그는 과거 상태를 담을 수 있다.
   현재 범위에서 제외된 항목을 이전 질문 목록만 보고 다시 물으면 불필요한 결정이 생긴다.
2. **목표 변경을 즉시 작업 범위에 반영한다.** UR 확정으로 범위가 좁아지면 SR 수정과
   시스템 세부 정책 질문도 함께 보류한다. 최초 요청을 그대로 유지하면 합의한 범위를 벗어난다.
3. **평가 기능과 자동 합격 기준을 구분한다.** 시각화와 지표를 제공하고 사람이 판단하는
   방식도 사용자 수용 기준이 될 수 있다. 수치 합격선이나 자동 판정을 반드시 요구하지 않는다.
4. **모호한 표현은 실제 작업 예시로 확인한다.** 이번에는 ‘같은 명령’을 이동·추적·공격으로
   구체화하자 다양성의 대상이 명확해졌다. 매번 다른 경로를 강제하는 조건도 피할 수 있었다.
5. **비교 데이터의 선택 범위와 평가자의 신원을 분리한다.** 이번 결정에 필요한 내용은
   학습 기록 하나 또는 여러 개를 사용할 수 있다는 점이었다. 특정 사람을 지정할 필요는 없었다.
6. **외부 기능 통합은 사용자가 관찰할 결과로 명세한다.** 연결 여부만으로 충분한지,
   실제 상황에서 처리하고 목표 시간까지 동작해야 하는지를 확인해야 수용 범위가 드러난다.
7. **이미 답한 내용을 다시 승인받는 질문은 줄인다.** 마지막 확인에서는 23시간과 기존
   24시간 목표의 차이를 확인하는 일과 전체 합의 재확인을 함께 요청했다. 사용자는 시간만
   정정했다. 필요한 질문은 남은 불일치에 집중하고, 나머지 결정은 명확한 답변에서 추적한다.
8. **상태 변경 근거를 항목별로 남긴다.** 어떤 답변이 어떤 수용 기준을 확정했는지 기록하면
   이후 SR 도출 시 사용자 결정과 시스템 설계 선택을 구분할 수 있다.

## 확인 범위와 후속 작업

UR 수정 후 `git diff --check`를 실행했고 공백 오류는 없었다. 줄바꿈 변환 경고는 있었다.
문서 작업이므로 코드 테스트나 실제 게임 실행 시험은 수행하지 않았다.

후속 SR 작업에서는 확정된 세 UR을 입력으로 사용한다. 다양성의 관찰 자료, 키 입력 비교
지표와 표시 방식, 외부 기능 시연의 기록 및 성공 판정 절차는 SR에서 구체화할 수 있다.
이번 답변에 없는 임계값·발생 횟수·실패 후 재개 정책을 사용자 합의로 취급하지 않는다.

이 로그는 기존 로그와 같이 `docs/logs/`에 저장한다. 해당 경로는 기존 `.gitignore`의
제외 대상이므로 로컬 작업 기록으로 남는다.
